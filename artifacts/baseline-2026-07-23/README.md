# Baseline run — jpjobs 0.2.0

This run captures the unmodified `jpjobs==0.2.0` behavior before data-quality
and source-adapter improvements.

## Experiment

- Run date: 2026-07-23
- Requested window: 2026-06-23 through 2026-07-23
- Location: all Japan
- Keywords: none
- Employment type: unrestricted
- Page limit: 2
- Sources: the 10 sources marked `active`

```bash
jpjobs \
  --sources=hellowork,linkedin,tokyodev,japandev,daijob,gaijinpot,jobsinjapan,green,forkwell,wantedly \
  --days=30 \
  --pages=2 \
  --format=json \
  --output=artifacts/baseline-2026-07-23/jobs.json
```

## Observed baseline defects

1. A keyword-free search did not remain keyword-free. LinkedIn automatically
   expanded it into 14 built-in IT-support searches and returned 81 rows tagged
   with implicit keywords.
2. HelloWork reported 31,913 matching listings but returned only 30 rows even
   though the requested page limit was 2.
3. Seven exact company-and-title matches appeared on both TokyoDev and
   JapanDev, but none were deduplicated.
4. Only 206 of 507 rows had a usable posted date. A 30-day request therefore
   could not be verified for most results.
5. Wantedly returned 13 rows older than the requested window because there was
   no global post-filter.
6. The absence of warnings does not prove that every source honored the
   requested filters or pagination.
